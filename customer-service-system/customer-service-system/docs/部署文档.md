# 电商数据分析 Agent · 部署文档

> 适用包：`release/ecom-analysis-agent.zip`（源码包，不含依赖与真实配置）。
> 解包后先按 §4 配好后端 `.env`，再按顺序执行 §3 → §5 → §6。

## 1. 环境要求

| 项 | 要求 |
| --- | --- |
| Node.js | 见 `frontend/package.json` 的 `engines`（建议 Node 22 LTS） |
| Python | 3.12+ |
| MySQL | 8.0+ |
| 大模型 Key | OpenAI 兼容接口（课程默认阿里百炼，见 §4） |

## 2. 解包与目录说明

```
ecom-analysis-agent/
├── backend/            # FastAPI 后端
│   ├── app/            # 路由 / Agent / MCP / 观测等源码
│   ├── data/seed/      # 业务数据种子脚本
│   ├── data/chroma/    # 本地向量库（随包提供，可直接用）
│   ├── uploads/        # 上传文件目录（含演示评价晒图）
│   ├── requirements.txt
│   ├── .env.example    # 配置模板（含示例值）
│   └── .env            # 空模板：key 齐全，关键值留空，部署时填写
├── frontend/           # Vue3 前端（含可直接部署的 dist/）
├── sql/ecommerce.sql   # 建表 + 演示账号（admin/aaa/bbb）
├── docs/               # 本文档所在目录
└── README.md           # 课程开发说明（含各 lesson 验证方法）
```

包内已剔除：`backend/.venv/`、`frontend/node_modules/`、`frontend/dist` 之外的构建缓存、
`.git/`、`.opencode/`、真实 `.env`。拿到包后需自行 `pip install` / `npm install`。

## 3. 准备数据库

先建空库（库名需与 `.env` 中 `DATABASE_URL` 一致）：

```sql
CREATE DATABASE ecom_analysis_agent DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

再导入初始化脚本（建全部表 + 演示账号；业务数据由 §5 的种子脚本生成）：

```powershell
mysql -u root -p ecom_analysis_agent < sql/ecommerce.sql
```

也可用 Navicat / DBeaver / MySQL Workbench 打开 `sql/ecommerce.sql` 执行。
后端启动时另有 `Base.metadata.create_all` 兜底建表，但**演示账号必须靠这个 SQL 导入**。

## 4. 后端部署

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

### 4.1 填写 `.env`

复制包内空白模板填写（`backend/.env`，key 齐全、关键值留空）：

| 配置 | 说明 |
| --- | --- |
| `DATABASE_URL` | **必填**，如 `mysql+pymysql://用户名:密码@127.0.0.1:3306/ecom_analysis_agent` |
| `JWT_SECRET_KEY` | **必填**，换成足够长的随机字符串（勿提交到公开仓库） |
| `JWT_EXPIRE_HOURS` | Token 有效期（小时），默认 `24` |
| `JWT_ALGORITHM` | 默认 `HS256`，一般不动 |
| `LLM_API_KEY` | **必填**，对话/诊断用的大模型 Key（课程默认百炼） |
| `LLM_BASE_URL` | OpenAI 兼容地址，百炼：`https://dashscope.aliyuncs.com/compatible-mode/v1` |
| `LLM_MODEL` | 课程默认 `qwen3.7-flash` |
| `LLM_TIMEOUT` | 单次调用超时（秒），默认 `60` |
| `LLM_MAX_RETRIES` | 失败重试次数，默认 `1`（对话场景不宜久等） |
| `EMBEDDING_API_KEY` | 留空即回退使用 `LLM_API_KEY`（同一百炼账号可直接复用） |
| `EMBEDDING_BASE_URL` / `EMBEDDING_MODEL` | 课程默认百炼 `qwen3.7-text-embedding-flash` |
| `EMBEDDING_TIMEOUT` | 默认 `60` |
| `CHROMA_PERSIST_DIR` | 向量库本地目录（相对 `backend/`），默认 `data/chroma` |
| `CHROMA_COLLECTION` | 默认 `ecom_docs` |
| `SEMANTIC_RELEVANCE_MAX_DISTANCE` | 语义检索相关度阈值，默认 `0.50`（换向量模型需重标定） |

注意：

- **换向量模型（`EMBEDDING_MODEL`）后必须重跑 §5 的 `index_vectors` 重建向量库**，否则检索质量无保障。
- 改 `.env` 后需重启 uvicorn。
- MCP Server **不必单独启动**：对话跑图时主程序以 stdio 子进程拉起
  `python -m app.mcp_server.server`。

### 4.2 启动后端

```powershell
cd backend
.\.venv\Scripts\Activate.ps1
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

- 健康检查：<http://127.0.0.1:8000/>
- 接口文档：<http://127.0.0.1:8000/docs>

## 5. 初始化业务数据与向量库

**清空范围**：商品、订单、评价，以及 Agent 产物与观测数据
（诊断报告、预警、运行记录、步骤、反馈）。**保留用户表**（演示账号清掉就没法登录）。
只在教学库执行；清空与重插在同一事务，失败回滚。重跑后评价 id 会变，因此向量库要重建：

```powershell
cd backend
.\.venv\Scripts\Activate.ps1
python -m data.seed.seed_ecommerce
python -m data.seed.index_vectors
```

说明：包内已带一份 `data/chroma/`（随种子数据生成）。如果跳过本节直接用包内向量库，
必须保证数据库也是与之配套的（即同样由种子脚本生成的数据）；**凡重跑 `seed_ecommerce`
就必须重跑 `index_vectors`**。

## 6. 前端部署

### 6.1 开发运行

```powershell
cd frontend
npm install
npm run dev
```

开发地址一般为 <http://127.0.0.1:5173>。
`frontend/.env.development` 默认 `VITE_API_BASE_URL=http://127.0.0.1:8000`；
开发模式下 Vite 已将 `/api`、`/uploads` 代理到 `127.0.0.1:8000`。

### 6.2 生产部署

```powershell
cd frontend
npm install
npm run build   # 产物在 frontend/dist/（包内已带一份本次构建结果）
```

- 生产后端地址与开发不同时，新建 `frontend/.env.production`
  （如 `VITE_API_BASE_URL=http://线上IP:8000`）后重新 `npm run build`
  （构建时烘焙进产物；不建则默认走相对路径 `/api`，仅适合前后端同源部署）。
- 静态部署（nginx）时给 SPA 配 fallback：`try_files $uri /index.html`，
  否则刷新 `/manager/*` 路由会 404。

## 8. 生产注意事项

1. **CORS**：`backend/app/main.py` 的 `origins` 仅放行 `5173` 两个开发源；
   前后端分离部署时必须把生产前端源加进去。
2. **密钥**：`JWT_SECRET_KEY`、`LLM_API_KEY` 等不得提交到公开仓库，对外分享用占位值。
3. **人工确认是单进程锁 + MemorySaver 检查点**：重启后待确认任务失效；
   多进程部署需要共享检查点与动作幂等机制（见 `README.md` 说明）。
4. **只读诊断约束**：Agent 工具禁止改订单/库存/价格/上下架；SQL 执行最多返回 200 行。

## 9. 常见问题

| 现象 | 排查 |
| --- | --- |
| 后端启动报数据库连接错误 | MySQL 是否启动、库是否创建、`.env` 中 `DATABASE_URL` 账号密码是否正确 |
| 前端登录后接口 401 | 后端是否启动；清浏览器站点数据后重登（过期 token） |
| 对话报错鉴权/模型相关 | 先查 `LLM_API_KEY` / `LLM_BASE_URL` / `LLM_MODEL` 是否填写正确；改 `.env` 后重启 |
| 语义检索命中差、无关 | 是否换过向量模型没重建库：重跑 `python -m data.seed.index_vectors` |
| 有图评价搜不到图片内容 | `index_vectors` 时无 Key 或 vision 调用失败会降级纯文本；配好 Key 后重跑 |
| 上传/评价晒图 404 | 确认 `backend/uploads` 存在可写；生产部署确认 `/uploads` 静态挂载与代理 |
| 导入 SQL 后登录失败 | 确认连的是导入过 `ecommerce.sql` 的库；`admin` 密码为 `admin` |
