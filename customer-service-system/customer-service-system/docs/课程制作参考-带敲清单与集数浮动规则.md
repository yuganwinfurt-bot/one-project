# 课程制作参考：带敲清单与集数浮动规则

> 用途：录课前对照用的**内部参考**，不是学员笔记（学员笔记见 `docs/笔记/`）。
> 这份表**不冻结**：顺序、拆分、行数都可以随时调；行数按当前仓库实测，改代码后回来更新对应行。
> 核心原则：**集数是结果，不是目标**。固定的是"每集怎么讲"（40 分钟、一行一讲、手敲 50~90 行），集数随之浮动。

---

## 一、固定什么、浮动什么

| 固定 | 浮动 |
| --- | --- |
| 每集时长 35~40 分钟 | 集数（按现有内容量排下来大约 18~24 集） |
| 每集手敲 50~90 行，一行一讲 | 每个主题占几集（难拆易合） |
| 每集结尾能跑通一个可验证的增量 | 主题的先后微调 |
| 前端与样板一律不敲（给代码 + 讲解） | — |

**为什么集数浮动**：总时长由内容量决定，不由集数决定。必敲 ~1470 行，按"一行 15~30 秒"算＝纯敲 370~735 分钟，加上讲解、演示、验证，总计 **12~16 小时**。把它分成 18 集还是 24 集，总时长不会变，变化的是每集挤不挤：

- **拆** → 集数多，每集 40~60 行，讲得从容，适合难点；
- **合** → 集数少，每集 90 行以上，就要么压缩讲解、要么延长到 50 分钟以上，通常得不偿失。

**结论**：先按主题排顺序，再按"每集能不能在 40 分钟内一行一讲讲透"决定拆还是合。排出来 18~24 集都正常。

## 二、预算口径（按"边写边讲"）

关键口径不是打字速度，而是**一行的屏幕时间**：敲下这一行 3~8 秒，把它讲清楚（为什么这么写、参数是什么、下一步做什么）10~25 秒，合计 **15~30 秒/行 → 2~4 行/分钟**。

| 每集时长 | 可用于写代码的镜头时间 | 每集可手敲 |
| --- | --- | --- |
| 35 分钟 | 15~17 分钟 | 30~68 行 |
| 40 分钟 | 18~20 分钟 | 36~80 行 |
| 45 分钟 | 20~23 分钟 | 40~92 行 |

对照参考：免费项目《智能实验室预约系统》25 小时录播 ≈ 1500 分钟，按同一口径约 3000~6000 行——同类项目通常要 20 小时以上。

## 三、每集节奏模板（40 分钟）

| 环节 | 时间 | 说明 |
| --- | --- | --- |
| 演示成品 | 3 分钟 | 先看这一集做完长什么样 |
| 讲原理 | 8~10 分钟 | 画图讲清"为什么这样设计"，包括反例 |
| 手敲 | 20~24 分钟 | 50~90 行，一行一讲，边敲边跑 |
| 跑通验证 | 3~4 分钟 | 用示例问题或接口验收本集增量 |
| 小结与预告 | 2 分钟 | 这一集改了哪个文件、下一集接什么 |

## 四、主题清单与手敲量（按顺序，集数待定）

**顺序上有一条硬约束**：业务数据与读取接口必须在对话之前——先把商品、订单、评价做成能查的模块，后面 NL2SQL、路由、动作决策才有真实数据可演示。

| 顺序 | 主题 | 手敲 | 拆 / 合建议 |
| --- | --- | --- | --- |
| 1 | 项目介绍和效果演示 | 0 | 一集 |
| 2 | 环境与数据底座 | ~40 | 可拆：环境 / 表设计与种子数据（拆后各 ~25） |
| 3 | 业务读取模块（商品 / 订单 / 评价） | ~80 | 一集讲透最省时间，不建议拆 |
| 4 | SSE 对话骨架 | ~90 | 一集 |
| 5 | NL2SQL | ~100 | 可拆：生成 SQL / 校验与提示词 |
| 6 | SQL 安全与自纠 | ~80 | 可拆：白名单与绕过攻防 / 限流与报错自纠 |
| 7 | 向量检索与索引 | ~90 | 可拆：入库与索引 / 检索与距离含义 |
| 8 | 查询路由 | ~120 | 建议拆：规则 / 信号与兜底（拆后各 ~60） |
| 9 | 多轮对话与短期记忆 | ~60 | 可与 8 合并（同属"理解问题"），合后 ~160 需两集 |
| 10 | LangGraph 状态图 | ~110 | 建议拆：图结构与状态 / 节点与条件边 |
| 11 | 证据准备 | ~70 | 可与 12 合并 |
| 12 | 多智能体调度与过程事件 | ~80 | 可与 11 合并（合后 ~140 → 拆两集或延到 45 分钟） |
| 13 | 动作决策 | ~90 | 一集 |
| 14 | 人工确认门 | ~80 | 可与 15 合并 |
| 15 | 动作执行与并发保护 | ~80 | 可与 14 合并（合后 ~140，同上） |
| 16 | MCP Server（最小版） | ~110 | 可拆：最小可用版 / 工具与参数设计 |
| 17 | MCP Client 接入 | ~60 | 建议与 16 合并（同一件事的两端） |
| 18 | 可观测 | ~70 | 可拆：写入 / 历史与反馈 |
| 19 | 多模态 | ~60 | 可合进收尾 |
| 20 | 整体走查 | 0 | 一集 |

**合计必敲 ≈ 1470 行**（含上表全部主题）。

拆合之后再算一次：全拆约 28 个主题单元、全合约 15 个，所以最终集数落在 **18~24 集**；推荐 **20~22 集**（难点拆、简单合，不用凑整）。

## 五、拆集 / 合集的判断标准

**该拆的信号**（任一命中就拆成两集）：

- 手敲超过 90 行；
- 一集里要引入两个以上彼此独立的新概念（例：路由规则 + 多轮记忆）；
- 现场需要调模型行为（SQL 生成质量、prompt 调优），排错时间不可控；
- 结尾没办法用一个可验证的增量收尾。

**该合的信号**（两条都命中才合）：

- 两个主题强耦合，分开讲要互相引用（例：MCP Server 与 Client）；
- 各自手敲都低于 50 行。

**不要为凑整拆或合**：集数是排出来的结果，不是排之前定好的数字。

## 六、可给代码（讲清思路即可，约 1250 行）

| 内容 | 处理方式 |
| --- | --- |
| 业务模块的前端列表页与详情抽屉（商品 / 订单 / 评价 / 诊断报告） | 在业务模块那一集给代码，讲"接口定好后页面怎么接" |
| 多轮第二层（隐含承前）、多轮第三层（LLM 改写） | 给代码 + 讲设计 |
| 入口兜底（闲聊 / 无关 / 过短） | 给代码 + 讲判定顺序与误伤边界 |
| SQL 报错自纠重试、结构化失败回退语义、统计失败不冒充 | 给代码 + 讲"为什么不能拿片段冒充统计" |
| 证据合并的细节（图片描述合并、按商品归属计数、距离阈值过滤） | 给代码 + 讲取舍 |
| 可观测的辅助函数、观测看板统计接口、图表组合式函数 | 给代码 |
| 前端其余页面（对话页、首页看板、观测看板、语义检索页） | 给代码 + 讲结构与状态共享 |
| 一键巡检、预警已读、消息提醒 | 给代码 + 讲"同一张图被系统触发" |
| 后端与前端测试（1473 行） | 不敲，讲"成品代码里怎么验的" |

## 七、三个会击穿预算的风险

1. **模型行为不稳定**：SQL 生成、prompt 调优这类内容现场排错时间不可控（"聚合 SQL 撞数据库严格模式"就是活例子）。对策：这类片段预录，或用成品代码讲。
2. **临时加需求**：录制期间每加一个功能都要重新估时长。对策：不改正课清单。
3. **正课手敲版与成品代码偏差**：成品迭代后两者不一致，学员对照会困惑。对策：每集说明差异在哪、成品代码里对应哪一段。

## 八、维护提示

- 录课前跑 `python -m data.seed.seed_ecommerce` 会把商品/订单/评价与 Agent 产物（诊断报告、预警）
  以及观测数据（运行记录、步骤、反馈）一起清空重建，用户账号保留；接着跑 `python -m data.seed.index_vectors` 重建向量库；
- 本表行数来自当前仓库实测，代码改动后回来更新第四节；
- 每次新增功能后问一句："这是正课手敲，还是给代码？"——默认是后者；
- 录制时若某集明显超时或讲不透，先按第五节的信号拆集，不要压讲解时间；
- 集数变动后，只更新本文件的顺序与拆分建议，不必回头改动已录集数的编号。
