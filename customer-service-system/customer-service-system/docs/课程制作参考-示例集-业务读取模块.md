## 一、本集目标与设计意图

**目标**：把商品、订单、评价三张表做成"能查"的只读模块——模型 → 出参模型 → 列表接口（分页 + 关键词过滤），前端列表页随课给代码。

**设计意图（要讲的第一个道理）**：**只读是刻意的**。这三张表只提供查询，不提供任何修改入口——后面 Agent 要写数据时，只能走诊断报告/预警这些"允许的动作"（人工确认那一集讲）。先把这条边界在代码层立起来，比事后用提示词约束可靠得多。

**第二个道理**：这一集是后面所有集的"数据地基"。NL2SQL 生成 SQL 时要知道表结构、路由要按商品名匹配、动作决策要按商品归属计数——都建立在这一集的三张表和接口之上。

## 三、数据模型关系（建议边讲边画）

```
products ──1:N──> orders      (orders.product_id)
products ──1:N──> reviews     (reviews.product_id)
orders   ──1:0..1──> reviews  (reviews.order_id，可空)
```

要点：`reviews.order_id` 允许为空，所以读取端一律按"可能没有评价"处理——订单详情里那一段必须先判存在性。

两个方向要分清（演示数据只体现了第二个）：

- 「评价没有订单」：模型允许，但**演示数据里不存在**（46 条评价全部挂着订单）。真实平台会有平台导入、无单评价这类来源，字段留了空值口子；本项目没走这条分支。
- 「订单没有评价」：**数据里有 3 笔**（就是状态演示用的已支付 / 已发货 / 已取消订单）。所以验证"该订单暂无评价"的空状态，直接点这 3 笔即可，不需要改动数据。

## 四、三张表的字段（照敲用）

与 `sql/ecommerce.sql`、`app/models/*.py` 逐字对应。`id / create_time / update_time` 是三个公共字段，定义在 `Base` 里，业务表不重复写。

**products（商品）**

| 字段 | 类型 | 约束 / 默认 | 说明 |
| --- | --- | --- | --- |
| name | varchar(100) | 必填 | 商品名称 |
| category | varchar(50) | 必填 | 类目 |

**reviews（评价）**

| 字段 | 类型 | 约束 / 默认 | 说明 |
| --- | --- | --- | --- |
| product_id | int | 必填、外键 `products.id` | 被评价的商品 |

| 字段 | 类型 | 约束 / 默认 | 说明 |
| --- | --- | --- | --- |
| id | int | 主键、自增 | 全表统一，业务表不重复声明 |

## 五、手敲代码（≈75 行）

### 5.1 `backend/app/models/product.py`（25 行，另外两张照着补、给代码）

```python
"""电商核心表：商品"""

from decimal import Decimal

from sqlalchemy import Numeric, String, Text
from sqlalchemy.orm import Mapped, mapped_column

from app.database import Base


class Product(Base):
    """商品表

    review_status 只表示是否待人工复核，与上下架无关；
    上下架状态不允许 Agent 修改。
    """

    __tablename__ = "products"
    __table_args__ = {"comment": "商品表"}

    name: Mapped[str] = mapped_column(String(100), nullable=False, comment="商品名称")
    category: Mapped[str] = mapped_column(String(50), nullable=False, comment="类目")
    description: Mapped[str] = mapped_column(Text, nullable=False, comment="商品描述")
    price: Mapped[Decimal] = mapped_column(Numeric(10, 2), nullable=False, comment="售价")
    stock: Mapped[int] = mapped_column(nullable=False, default=0, comment="库存数量")
    shelf_status: Mapped[str] = mapped_column(
        String(20), nullable=False, default="on_sale", comment="上下架状态"
    )
    review_status: Mapped[str] = mapped_column(
        String(20), nullable=False, default="normal", comment="人工复核状态"
    )
```

**讲解点**：
- `id / create_time / update_time` 在 `Base` 里统一定义（给代码看一眼即可），业务表不重复写；
- `Mapped[...]` + `mapped_column` 是 SQLAlchemy 2.0 的写法，类型注解与列定义写在一起；
- 金额用 `Numeric(10, 2)` 而不是 `Float`：钱不能用浮点数；
- 状态字段用字符串常量而不是数字（`on_sale` 比 `1` 可读，代价是占点空间，这个量级无所谓）；
- 顺手讲一句：为什么注释里强调"不允许 Agent 改上下架"——这是把安全边界写进模型，后面做工具白名单时要用。

### 5.2 `backend/app/schemas/ecommerce.py` 的 `ProductItem`（15 行）

```python
class ProductItem(BaseModel):
    id: int
    name: str
    category: str
    description: str
    price: Decimal
    stock: int
    shelf_status: str
    review_status: str
    create_time: datetime | None = None

    model_config = ConfigDict(from_attributes=True)

    @field_serializer("price")
    def _price(self, v: Decimal) -> float:
        return float(v)

    @field_serializer("create_time")
    def _time(self, v: datetime | None) -> str | None:
        return v.strftime("%Y-%m-%d %H:%M:%S") if v else None
```

**讲解点**：
- 为什么不直接把 ORM 对象返回：出参模型是一层契约，能挡住"以后给表加了个敏感字段就顺带吐出去"；
- `from_attributes=True` 让 pydantic 能从 ORM 对象取值；
- `field_serializer` 处理两件小事：`Decimal` 转 `float`（前端好处理）、时间统一格式（前端不用再格式化）；
- **前后端约定**：时间统一 `YYYY-MM-DD HH:MM:SS` 字符串，前端不解析直接显示。

### 5.3 `backend/app/services/ecommerce_service.py` 的 `list_products`（20 行）

```python
def list_products(
    db: Session,
    page: int,
    page_size: int,
    keywords: str | None = None,
) -> PageResponse:
    query = db.query(Product)
    if keywords:
        like = f"%{keywords.strip()}%"
        query = query.filter(or_(Product.name.ilike(like), Product.category.ilike(like)))
    total = query.count()
    rows = (
        query.order_by(Product.id.asc())
        .offset((page - 1) * page_size)
        .limit(page_size)
        .all()
    )
    return PageResponse(
        list=[ProductItem.model_validate(r) for r in rows],
        total=total,
    )
```

**讲解点**：
- `total` 要在 `offset/limit` **之前**取（加过 filter 之后），否则总数会把筛选条件丢掉；
- `ilike` + `%kw%` 做不区分大小写的模糊匹配；`keywords.strip()` 处理用户粘进来的空格；
- ORM 的参数化查询天然挡住 SQL 注入——但**不要因此以为"SQL 安全"这节课就没事了**：这里写的是固定 SQL，NL2SQL 那一集是让模型写 SQL，风险完全不同；
- 分页算法 `(page - 1) * page_size` 顺手推导一遍（第 1 页 offset 0）。

### 5.4 `backend/app/api/ecommerce.py` 的 `GET /products`（15 行）

```python
@router.get("/products")
def get_products(
    _user: CurrentUser,
    db: DbSession,
    page: Annotated[int, Query(ge=1)] = 1,
    page_size: Annotated[int, Query(ge=1, le=100)] = 10,
    keywords: str | None = None,
):
    """分页查询商品（只读）。"""
    return Response.success(
        data=ecommerce_service.list_products(db, page, page_size, keywords)
    )
```

**讲解点**：
- `CurrentUser` 依赖保证必须登录（这一集不区分角色，列表谁都能看）；
- `Query(ge=1, le=100)` 是**后端死守上限**：超出范围直接拒绝（HTTP 422 + `{"code":422,"message":"请求参数校验错误"}`），不是悄悄截断——想要截断得自己写 `min(page_size, 100)`；
- 统一响应体 `Response.success(data=...)`（给代码看一眼，讲"前端拦截器按 `code` 判断成败"）。
